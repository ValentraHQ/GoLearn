# Authoring curriculum content

All content lives in `internal/content/data/` as Markdown, is embedded into the binary, parsed and validated at startup, and verified in CI by actually compiling and running the code.

```
data/
  modules/NN-name.md     one file per module, with all of its lessons
  challenges/*.md        coding challenges
  projects.md            projects
  glossary.md            glossary terms
```

## Headings

- `# Title` — the module (or file) title, followed by `key: value` metadata lines
- `## Item` — a lesson / challenge / project / term, followed by `key: value` lines
- `### Section` — free-form body

Headings inside code fences are ignored. Prose directly after a `#`/`##` heading must be in a `###` section.

## Modules

```markdown
# Concurrency
id: concurrency
number: 11
track: advanced            # core | advanced | devops | advanced-go | architecture | security | microservices
paths: beginner, pro       # which learning paths show it
skill: concurrency         # default skill for lessons
requires: errors           # prerequisite module ids (locking is advisory)
project: concurrent-job-processing-system
summary: One sentence.
```

## Lessons

```markdown
## Goroutines
slug: goroutines
minutes: 7
challenges: worker-pool-results        # optional, comma separated challenge ids
objectives: A; B; C                    # semicolon separated
takeaways: A; B; C
status: planned                        # optional: a title on the roadmap with no content yet

### Concept        — Markdown (tables, lists, diagrams in ```text fences, > [!NOTE] callouts)
### Example        — prose + one or more code fences (```go is runnable; ```go norun, ```bash, ```json, ```yaml, ```sql are display-only)
### Exercise       — prompt, a ```text expect block, and a ```go solution block
### Check          — questions (see below)
```

**Exercises.** Mark the part learners must write with `// BEGIN` / `// END` inside the solution. The starter is generated by replacing that region with a TODO comment; the solution is the same file without markers. Learners pass when their program's stdout equals `expect` (trailing whitespace ignored). Use `// BEGIN` inside `switch` bodies or at top level as needed. To supply a hand-written starter use a ```` ```go starter ```` block instead.

**Questions.**

```markdown
Q: What does this print?
T: output              # mcq | tf | output | debug | multi | short
```go
fmt.Println("a", "b")
```
- [x] a b
- [ ] ab
E: Explanation shown after the attempt.
```
- `mcq`, `output`, `debug`: exactly one `[x]`; `multi`: any number; `tf`: use `A: true|false`; `short`: `A: answer | alternative`.
- **`output` questions are executed by CI**: the snippet is wrapped in `main` (unless it defines `func main()`), run, and its stdout lines joined with ` / ` must equal the option marked `[x]`.

## Challenges

```markdown
## fizzbuzz                 # the heading is the id
title: FizzBuzz
difficulty: beginner        # beginner | intermediate | advanced | expert
module: control-flow
lesson: control-flow/for-loops
skill: functions

### Problem   ### Input (optional)   ### Expected (optional)
### Constraints   (bullets)   ### Hints   (bullets)
### Starter   ```go``` — compiles, has `func main() {}`, and must FAIL the tests
### Tests     ```go``` — `package main`, `func TestXxx(t *testing.T)`; hidden from learners until submitted
### Solution  ```go``` — must pass the tests, with the race detector
### Explanation
```

## Projects and glossary

Projects: `level` (`beginner|intermediate|advanced|capstone`), `module`, `skills`, `hours`, sections *Summary*, *Description*, *Requirements* (bullets), optional *Architecture* (```` ```text ````), *Tasks* (`- title :: notes`), *Stretch*.

Glossary terms: `related: module/lesson, …`, sections *Simple*, *Technical*, optional *Code* (a complete program — CI runs it).

## Checking your work

```bash
CONTENT_ONLY=my-module/ go test ./internal/content -run TestContentRuns -v   # just your lessons
go test ./internal/content -count=1                                        # everything (~2 min)
```

The validator rejects: unknown skills/modules/lessons/challenges, published lessons without objectives/takeaways/example/quiz, questions without a correct answer or explanation, duplicate ids. CI additionally fails when an example doesn't run, an exercise solution doesn't print `expect`, a starter already prints `expect`, a challenge solution fails its tests, a challenge starter passes its tests (or doesn't compile), or a quiz answer is wrong.

Good lessons: one idea, ≤ ~150 words of explanation, idiomatic current Go, a runnable example, an exercise that needs *thought* rather than typing, and a quiz that tests understanding — not trivia.
